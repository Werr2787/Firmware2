# Drone Mission — Autonomous Navigation with QR Scanning

ROS2 узел для автономного полёта дрона в Gazebo (PX4 + MAVROS).

## Версия 4: непрерывное распознавание камер во время полёта

- `/uav1/camera`: передняя камера из вашего рабочего примера. `/uav1/camera_down`: нижняя камера. Название «верхняя» не меняет направление камеры: здесь подключён именно прежний топик передней камеры.
- Каждая камера имеет свой поток OpenCV и свой QR-детектор. Обработка работает на всех этапах: взлёт, перелёты между точками, вход в комнату, осмотр и посадка.
- Callback изображения только копирует кадр и ставит его в очередь. Очередь хранит один ожидающий кадр: если вычисления медленнее видеопотока, старый ожидающий кадр заменяется свежим. Поэтому это непрерывная обработка свежих изображений, не гарантия обработки абсолютно каждого кадра.
- Распознавание пробует multi-QR и single-QR; если чтение не удалось — повышение контраста и увеличение изображения до 2 раз. Увеличение не восстанавливает детали, которых нет в исходном изображении.
- Подтверждение: два разных обработанных кадра в окне 3 секунд. Поза записывается в момент получения кадра, а не окончания вычислений.
- Если нижняя камера обнаружила QR-контур при перелёте к точке осмотра, дрон удерживает текущую позицию 1.5 секунды для повторного чтения. Это не останавливает проход через дверь. Повторная пауза не чаще раза в 4 секунды.
- QR, прочитанные при входе в комнату и в полёте, сохраняются. Повторное обследование той же комнаты не стирает найденные коды. Новое поколение наблюдений начинается один раз при пересечении плоскости двери; результаты обработки из предыдущего поколения игнорируются.
- При посадке отсутствующий или устаревший QR не разрешает снижение. Счётчики камеры отображаются поверх обработанного кадра.

### Диагностика пропуска нижнего QR

Посмотрите в журнале `[CAM/down]`: `rx` — сколько кадров получено, `processed` — обработано, `decode` — длительность распознавания в мс, `age` — возраст последнего принятого кадра, `replaced` — заменённые ожидающие кадры.

```bash
ros2 topic hz /uav1/camera_down
ros2 topic hz /uav1/camera
ros2 topic info /uav1/camera_down --verbose
```

Если `rx=0` или растёт `age`, проверьте имя топика, Gazebo-ROS bridge и QoS. Если `rx` растёт, но QR не читается, сохраните исходный кадр нижней камеры: необходимо проверить размер QR в пикселях, резкость и положение в кадре. Чёрный или белый экран, смазанный QR и отсутствие QR в поле зрения алгоритм не исправит.

Параметры в основном файле: `QR_CONFIRM_COUNT=2`, `QR_HOLD_TIME=1.5`, `QR_HOLD_COOLDOWN=4.0`, `QR_RESULT_MAX_AGE=1.5`, `QR_SERVO_MAX_AGE=0.35`. При смазанном изображении сначала уменьшите `FLY_STEP` с 1.0 до 0.5. Это длина «морковки» setpoint, а не строго заданная скорость в м/с.

Угловые точки осмотра дают обзор геометрии, но не гарантируют, что нижняя камера увидит каждый участок пола. Если QR вне кадра на всём маршруте, нужен дополнительный проход над ним или покрытие пола с учётом калибровки/угла обзора нижней камеры.

### Проверки

`python3 test_qr_stream.py` запускает офлайн-тесты с заглушками ROS: независимые потоки камер, настоящее распознавание синтетических QR, разные кадры подтверждения, сохранение QR при ENTER_ROOM, отсев устаревших результатов, зависание для чтения и смена комнаты по плоскости двери. Это не тест запуска Gazebo, PX4 или точной посадки.

## Возможности

- Взлёт и сканирование комнаты (QR-коды на полу и над проёмами)
- Навигация между комнатами (сопоставление ID пола с ID проёма)
- Формирование Path_Array без повторов
- Обход Г-образных комнат (frontier-based coverage)
- Посадка на платформу с точным совпадением массива QR
- Visual servoing при посадке (центрирование по QR нижней камеры)

## Архитектура

Один ROS2-узел, разбитый на 4 класса:

| Класс | Ответственность |
|-------|-----------------|
| `QrDetector` | Приём результатов двух потоков камер, сохранение QR, подтверждение по разным кадрам |
| `FlightController` | MAVROS setpoint'ы, arm, mode switching |
| `RoomExplorer` | Осмотр углов по лидару, пути A*, краткое зависание для QR |
| `MissionStateMachine` | Конечный автомат миссии |

### Конечный автомат

```
WAIT → PRESTREAM → ARMING → TAKEOFF →
ENTER_ROOM → SCAN_ROOM → SELECT_DOOR → GO_TO_DOOR →
PASS_DOOR → VERIFY_NEW_ROOM → ENTER_ROOM → ...
                                              ↓
                                    SCAN_PLATFORMS → LAND_ON_PLATFORM → AUTO_LAND
```

### Логика Path_Array

1. В каждой комнате дрон сканирует QR на полу (`ID_floor`) и над проёмами (`ID_doorway`)
2. Если `ID_floor == ID_doorway` и этого ID нет в Path_Array → пролёт через дверь
3. Если ID уже в Path_Array → повторное сканирование комнаты
4. Path_Array строится последовательно: `[4] → [4, 11] → [4, 11, 6, 10, 9]`

### Логика платформ

1. В финальной комнате дрон находит 3 платформы с QR-массивами
2. Сравнивает Path_Array с массивом каждой платформы
3. При точном совпадении → visual servoing + посадка
4. QR-код платформы может быть закодирован как:
   - JSON: `[4, 11, 6, 10, 9]`
   - Строка без разделителей: `4116109` (сравнивается как конкатенация Path_Array)
   - Разделённый запятыми: `4,11,6,10,9`

### Осмотр комнаты по лидару (lidar_mapper.py)

1. **Замер стен** (~1.5 с зависания): лидар 360° строит карту, многоугольник комнаты и расстояния до каждой стены. Форма определяется автоматически: прямоугольная / Г-образная (есть вогнутый угол).
2. **Проёмы ~2 м**: разрыв в стене (лучи «близко → далеко → близко»), ширина 1.3–2.8 м, подтверждение в 3 сканах. Проём закрывается виртуальной стенкой, чтобы карта комнаты не «протекала» в соседнюю.
3. **Взгляд на проёмы**: из стартовой точки фронтальная камера поворачивается прямо на найденные проёмы — QR над ними читаются сразу.
4. **Углы**: для каждого выпуклого угла между двумя стенами — точка в **2 м от обеих стен** (по биссектрисе), 3 направления взгляда внутрь комнаты. Если комната узкая, отступ уменьшается до 1.6 / 1.2 / 0.9 м.
5. **Тени Г-комнаты**: открытая сторона многоугольника (за выступом) даёт точку осмотра в 1 м от неё; после прилёта карта пересчитывается и появляются углы второго крыла.
6. Перелёты — по A* с отступом 0.6 м от стен. Осмотр заканчивается сразу, как только выполнены условия комнаты.

Окно `lidar_map`: белое — стены по лидару, зелёный контур — стены комнаты с расстоянием до дрона, жёлтый — открытые стороны, розовый — проёмы с шириной, оранжевые круги — углы, красный крест — внутренний угол Г, голубые — точки осмотра (номер и направления взгляда), синий — путь, красный треугольник — дрон. Справа — размер, площадь, расстояния до стен по 4 осям, Path_Array.

Параметры: `CORNER_OFFSET`, `DOOR_WIDTH`, `DOOR_MIN/MAX`, `SAFETY_MARGIN` в `lidar_mapper.py`; `SHAPE_SCAN_TIME`, `MAX_VIEWPOINTS`, `FLY_STEP`, `SHOW_LIDAR_WINDOW` в основном файле.

## Установка

### Зависимости

```bash
sudo apt install ros-humble-mavros-msgs ros-humble-cv-bridge
pip3 install opencv-contrib-python numpy
```

### Сборка пакета

```bash
# Создать рабочее пространство
mkdir -p ~/drone_ws/src
cp -r drone_mission ~/drone_ws/src/

# Сборка
cd ~/drone_ws
colcon build --packages-select drone_mission
source install/setup.bash
```

### Альтернатива (без пакета)

```bash
# Просто запустить Python-файл напрямую
python3 autonomous_drone_mission.py
```

## Запуск

### Предварительные условия

1. Gazebo с PX4 запущен
2. MAVROS запущен и подключён:
   ```bash
   ros2 run mavros mavros_node fcu_url:=udp://:14540@localhost
   ```
3. Топики доступны:
   - `/uav1/mavros/state`
   - `/uav1/mavros/local_position/pose`
   - `/uav1/scan` (лидар)
   - `/uav1/rangefinder`
   - `/uav1/mavros/imu/data`
   - `/uav1/camera_down` (нижняя камера)
   - `/uav1/camera` (передняя камера)

### Запуск миссии

```bash
# Через launch file
ros2 launch drone_mission mission_launch.xml

# Или напрямую
ros2 run drone_mission autonomous_drone_mission

# Или как Python-скрипт
python3 autonomous_drone_mission.py
```

## Конфигурация

Основные параметры в начале файла `autonomous_drone_mission.py`:

| Параметр | Значение | Описание |
|----------|----------|----------|
| `NS` | `/uav1` | Namespace дрона |
| `SCAN_ALT` | `2.0` | Высота сканирования, м |
| `GRID_RES` | `0.5` | Размер ячейки покрытия, м |
| `COVERAGE_RADIUS` | `4.0` | Радиус сканирования, м |
| `YAW_DWELL` | `0.6` | Время осмотра направления, с |
| `QR_CONFIRM_COUNT` | `2` | Разных кадров для подтверждения QR |
| `POS_TOL` | `0.2` | Tolerance позиции, м |
| `SHOW_WINDOWS` | `True` | Показ окон камер OpenCV |
| `FORCE_ARM` | `True` | Принудительный arm (симулятор) |
